Idea 08 of 19 · The nineteen ideas

Move recurring fixes from per-occurrence agent corrections into executable checks (lint rule, CI step, routine)

On this page
  1. What was said
  2. How to apply it
  3. When it is useful
  4. Qualification

What was said

From 08:02, Boris's post argues that moving things into code improves efficiency: an agent can fix an issue every time it sees it, but that spends tokens and may miss cases. If Claude instead writes a lint rule, a CI step, or a routine, the whole class of issue can be automated permanently. Boris ties this to what people mean by loops: automating entire types of busywork rather than solving instances one at a time. Theo notes the idea is not new.

How to apply it

When an agent (or you) has corrected the same class of issue more than once, stop fixing occurrences and add an executable check that catches the class: a custom lint rule, a CI gate, or a small script. Write the check once, let it run on every change.

When it is useful

Any recurring correction — style, safety, architecture — that is currently handled by repeated review comments or repeated agent fixes.

Qualification

Argument, not a measured result. A wrong or over-broad check silently blocks good changes, so review executable checks like any other code.
