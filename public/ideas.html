Ideas

What Theo does, what he tells you to do, and what he's still working out

Nineteen ideas from the July 21, 2026 video, sorted by what is behind each one — a practice he runs, a directive he gives, or an opinion he offers as one. Every idea opens the video at the second it was said.

Detailed extraction · Structured ideas file

01 / What he does

What he actually does

Backed by something Theo did: a practice he runs, or a story from a real codebase.

  1. [02]

    Design tiny two-actor end-to-end tests that catch whole classes of failure

    Theo (recounting his time at Twitch)

    Distributed or multi-party features (chat, notifications, sync, webhooks) where component tests pass but integration breaks.

    03:46Theo, anecdote

  2. [05]

    Build small tool adapters for things the CLI cannot do (video/asset uploads to PRs)

    Theo

    Recurring agent tasks blocked by a missing API surface: media attachments, screenshots, signed artifacts, anything possible by hand but not by tooling.

    05:52Theo, anecdote

  3. [11]

    Treat newcomer questions as a signal for onboarding gaps (Theo's dumb-questions practice)

    Theo

    Any team onboarding engineers, and equally for agents: an agent's repeated confusion is the same signal.

    11:14Theo, practice

  4. [13]

    Use steering files to make the agent say no (and to get fast feedback when things go wrong)

    Theo

    Projects that attract repeated out-of-scope requests from users, teammates, or agents.

    13:03Theo, practice

  5. [14]

    Compose layers so type safety runs end to end — and expect that click more often now

    Theo

    Any stack where hand-written duplicates of a single source of truth drift apart.

    13:51Theo, anecdote

  6. [19]

    Solo projects now exceed your own comprehension — build systems so you and your agents don't get lost

    Theo

    Solo developers and small projects where all context is tacit and agent-generated code outpaces personal recall.

    18:00Theo, anecdote

02 / What he tells you

What he tells you to do

Directives — Theo's own, and Boris's as Theo quoted and endorsed them on camera.

  1. [03]

    Infra and DX automation now speeds up every agent, not just you

    Boris (as quoted by Theo), endorsed by Theo

    When deciding where to invest tooling effort on a team running multiple concurrent agent sessions.

    04:47Boris's post, read by Theo

  2. [08]

    Move recurring fixes from per-occurrence agent corrections into executable checks (lint rule, CI step, routine)

    Boris (as quoted by Theo)

    Any recurring correction — style, safety, architecture — that is currently handled by repeated review comments or repeated agent fixes.

    08:00Boris's post, read by Theo

  3. [10]

    Encode domain knowledge as infrastructure so newcomers' agents get steered too

    Boris (as quoted by Theo), partially endorsed by Theo

    Codebases where the same contextual rules are re-taught verbally to every new engineer.

    09:56Boris's post, read by Theo

  4. [12]

    Write your CLAUDE.md / AGENTS.md yourself; watch agent behavior and adjust

    Theo

    Anyone whose agent instructions were generated once and never deliberately revised.

    12:29Theo, directive

  5. [15]

    Write Claude.mds, review.mds, skills, and docs so agents work with zero prompting context

    Boris (as quoted by Theo), endorsed by Theo

    Any shared codebase; the test is whether a stranger's first prompt succeeds.

    14:33Boris's post, read by Theo

  6. [16]

    Calibrate from a cold start: run minimal prompts first, add context only where it fails

    Theo

    New projects, newly agent-enabled repos, and any team tempted by large plugin lists.

    16:02Theo, directive

  7. [17]

    Instruction files should steer toward success, not list where things are

    Theo

    Auditing any existing instruction file that reads like a directory listing.

    16:38Theo, directive

03 / Still working out

What he's still working out

Offered as opinion, and flagged as opinion. The video says so itself for several of these.

  1. [01]

    Close the CI feedback loop: let the agent trigger CI and read failed logs itself

    Sponsor segment (Blacksmith), read by Theo

    Any repo where agents open PRs and CI results gate them, especially when humans currently relay errors by hand.

    01:53Sponsor segment

  2. [04]

    Preview environments matter more now that code is built outside your machine

    Theo

    Any agent workflow where the human cannot or should not run the app locally to review each change.

    05:06Theo, opinion

  3. [06]

    Authoring and testing a small skill has a tight, low-stakes feedback loop

    Theo

    Individual contributors hesitating to invest in tooling because it used to be high-effort, low-recognition work.

    06:30Theo, opinion

  4. [07]

    Teams are now more willing to fund tooling time — use it

    Theo

    Engineers who assume management still treats deep tooling as slacking.

    07:28Theo, opinion

  5. [09]

    Custom lint rules became economical: agents lower the cost of the code and its tests

    Theo

    Teams with a backlog of issues always caught by eye that were never worth the engineering cost.

    08:30Theo, opinion

  6. [18]

    Building environments where code lands well is a career-level skill (with a grain of salt)

    Theo (self-flagged as speculative)

    ICs aiming at senior/staff scope, and teams deciding what to recognize and promote.

    16:54Theo, opinion
