Guides

Thirteen guides, and what each one does not prove

Each guide names one recurring failure, gives a method concrete enough to run this week, says who it fits, and states the limits of what it verifies. They are grouped by the source each was adapted from: the video, two repository snapshots, and Boris Cherny's public work.

+ From Theo's video

Eight guides adapted from the July 21, 2026 video. Quotes in these guides are from the video; Boris quotes are Boris as quoted by Theo. Investigation: Theo: T3 Code and Melee.

Guides 01–08
  • 01Guide 01: Convert recurring failures into permanent rules

    For a developer on a team where the same mistake keeps coming back.

  • 02Guide 02: One critical journey test beats broad shallow coverage

    For a team whose product has one path that must never silently break.

  • 03Guide 03: Make previews usable from the agent's environment

    When work happens in several worktrees or machines and a person or agent needs to inspect the actual change.

  • 04Guide 04: Let the agent read and resolve CI failures

    When you repeatedly carry CI errors from a web page back into an agent prompt.

  • 05Guide 05: Put project knowledge where the next task needs it

    When an agent or newcomer repeatedly misses a project decision, convention or non-obvious fact.

  • 06Guide 06: Build small tool adapters for capability gaps

    For closing a specific gap between what your agent needs to do and what its existing tools can do.

  • 07Guide 07: Turn newcomer questions into improvements

    When teammates or agents repeatedly get stuck on the same first task.

  • 08Guide 08: Keep contracts consistent across the application

    When agents repeatedly invent mismatched data shapes between storage, APIs and the interface.

Guides 09–10
  • 09Guide 09: Verification contracts

    Make “done” mean a checked artifact, not a finished command.

  • 10Guide 10: Codebase navigation and tooling

    Find where to change code in an unfamiliar codebase, and wrap external tools so their failures are safe.

Two guides adapted from Matt Pocock's course-video-manager snapshot 4c1f3f5d49417e54b185bfe737b1e1a56f29c7b8. Investigation: Matt Pocock: Course Video Manager.

Guides 11–12
  • 11Guide 11: One domain language and one transport when an agent calls your API

    You are adding a command, route or agent verb to a codebase that already has a glossary and a deployed API.

  • 12Guide 12: Make pipeline artifacts reusable, resumable and honestly complete

    You run a pipeline with slow, expensive steps and want to reuse prior work, resume after crashes, and never accept a truncated artifact.

One guide generalised from the json-schema-to-typescript CI (fixtures, built-artifact smoke tests, fuzzing, a real-world corpus and conformance checks). Investigation: Boris Cherny: public engineering work.
