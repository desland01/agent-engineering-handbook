Report 01 · inspected evidence · Theo: T3 Code and Melee

Inspected code puts advice in context

Read the T3 Code and Melee inspection to separate advice, inspected code and measured results. Later code does not establish the setup at filming time.

  1. [01]A completion contract specifies the real output, how complete its inputs must be and the outcome its consumer sees.
  2. [02]Recurring mistakes need checks at existing lint, type, test and build boundaries that reject bad changes and accept valid ones.
  3. [03]Explicit ownership separates agent writes and test state, contains provider quirks in adapters and checks remote access to artifacts.
  4. [04]Project decisions stay beside relevant code, while evidence distinguishes local runs, remote CI, author reports and untested hardware.

Report 02 · inspected evidence · Matt Pocock: Course Video Manager

Shared language connects the inspected workflows

Read the course video project inspection for shared language and recovering interrupted work. Account association alone does not establish authorship.

  1. [01]Shared vocabulary, lasting decisions, bounded modules and callable agent APIs inform the lesson on speaking a codebase's language.
  2. [02]Output identity, resumable work and recovery from malformed results inform the lesson on artifacts that survive interruptions.
  3. [03]The report recommends making the intended outcome easy to request and hard to misreport.

Report 03 · inspected evidence · Boris Cherny: public engineering work

Different checks reveal different output failures

Read the public-project inspection for several ways to check useful output. Tests were inspected, not run locally.

  1. [01]The report discusses layered validation to test public output, reproduce new failures and preserve meaningful baselines.
  2. [02]Before-and-after measurements compare the same work to establish whether a change improved the result.
  3. [03]Existing lessons on lint, adapters and native loading provide supporting references for the skills.
