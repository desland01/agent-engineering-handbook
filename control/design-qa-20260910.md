# Design QA — Agent Engineering Handbook

**Verdict: No—not ready for design-director sign-off, because the reader’s sidebar competes with the article, the guide shelves still frame empty space as content, and the supplied mobile evidence could not be inspected.**

## Findings, in severity order

### 1. High — sidebar labels inherit the article’s display scale

**Page and width:** `guides/04-ci-feedback.html`, 1440px.

**What is wrong:** “ON THIS PAGE”, “THIS GUIDE” and “SEQUENCE” are oversized, widely tracked headings with excessive vertical separation, making orientation tools compete with the article instead of supporting it.

**Evidence:** [guides__04-ci-feedback-1440.jpg](evidence/guides__04-ci-feedback-1440.jpg), left rail beside the title and first article section: “ON THIS PAGE” wraps onto two lines; “SEQUENCE” arrives near the rail’s lower fade. The built HTML contains these labels as `aside.rail` h2 elements. In `build/assets/handbook.css:470–473`, `.rail h2` sets an 11px mono label, but the equally specific, later `.reader h2` at line 509 overrides its size, margin, line height and adds padding and a border. With the 16px root assumption, `--text-xl: 1.85rem` (line 41) resolves to 29.6px; the resulting top margin is 71.04px and top padding is 29.6px. These are cascade calculations, not browser-computed measurements.

**Rule broken:** `DESIGN.md:305–307`: “Rail labels ("On this page", "Sequence") are sidebar section labels, set small and sans, not kickers over a main heading.”

**Proposed fix—not applied:** Scope the section-heading treatment to `.reader article h2` rather than `.reader h2`, and explicitly restore the sidebar role:

```css
.reader .rail h2 {
  font-family: var(--font-sans);
  font-size: 14px;
  font-weight: 500;
  line-height: 1.3;
  letter-spacing: 0;
  text-transform: none;
  margin: 0 0 8px;
  padding-top: 0;
  border-top: 0;
}
```

Keep the existing inter-block rules on `.rail > div`; do not remove the rail’s navigation or source content to make it fit.

### 2. Medium — short guide shelves retain an empty outer box

**Page and width:** `guides.html`, 1440px.

**What is wrong:** The two-guide Melee and Course Video Manager shelves and the one-guide Boris shelf leave large, bordered blank remainders, making the directory look unfinished and repeating the blockiness diagnosed in design note 9.

**Evidence:** [guides-1440.jpg](evidence/guides-1440.jpg), the last three shelves below the eight-guide video shelf: the outlines continue across the unused right half, or right three quarters, of each row. The built HTML has respectively two, two and one `li.tile.guide` items in those lists. `build/assets/handbook.css:371–374` gives every list a full outer border and four equal columns from 1080px, regardless of item count. The child shadow correctly delineates populated cells, but the parent’s outline still encloses the blank remainder.

**Rule broken:** `DESIGN.md:109–113`: “Structure is drawn with hairlines: grids set `gap: 1px` and each cell paints its own `box-shadow: 0 0 0 1px var(--border)`, so neighbouring cells meet on one hairline and a partly filled last row shows ground instead of an orphan block.”

**Proposed fix—not applied:** Keep the four-column alignment and the existing individual-cell hairlines, but stop outlining unoccupied columns:

```css
.tiles.guides {
  border: 0;
  border-radius: 0;
  overflow: visible;
}
```

Retain `gap: 1px`, `background: var(--bg)` and the `.tile.guide` shadow. Verify the perimeter hairlines and hover/focus outline after this change; the proposal has not been rendered.
