# Nautilus skill loading and classification

The selected runtime exposes native skill descriptions and loads bodies on demand. An
explicit user request selects a user-only workflow even when it is absent from the
proactive catalog. Verify its native entry before reporting it missing; preserve its
invocation flags. Do not load an old catalog, every body or legacy memory as an
additional instruction hierarchy.

Use precise instructions for model-facing work and simple explanations for people.
Preserve evidence, scope and material limitations in both. The shared authoring method is
`nautilus-core:create-skill`; follow the user's selected workflow without making all
methods compulsory stages.

## Most tasks need more than one method

Read the catalog at intake, before the first substantive action, and name every method the
task needs. The ordinary answer is several. A long or composite assignment is a chain —
plan, then implement, then review — where each stage's output is the next stage's input.
State the chain before starting and load each method at the point it applies rather than
all at once. Invoking none of the methods you named is the failure this step exists to
prevent; where nothing in the catalog fits, say what you looked for and continue.

## A worker is given its methods, not left to guess

Delegated work carries the same selection, made by the parent. The capsule names the
worker's methods in the order they apply, beside the assignment, inputs, write ownership,
limits, deliverable and completion evidence. Admission refuses a method the parent does not
itself require, so the parent selects for the whole assignment tree before the first
dispatch rather than discovering a missing method at hand-off.

## Classification and capacity

Core is shared operating and engineering expertise used across business domains. Domain
is expertise selected for the business, its work or its technology. Purpose determines
category; folder, publisher, model visibility and explicit user invocation do not.
User-only skills count in the category matching their purpose.

The current versioned declaration records category allowances and targets. Neither
category borrows places from the other. Where the declaration requires distinct-purpose
justification above its target, explain why extending an existing skill cannot serve the
purpose. At the hard cap, uniqueness alone admits no further skill: combine the useful
expertise into an existing method, or justify replacing an active skill that is already
covered or no longer needed. Preserve its original and useful expertise inactive, repair
affected references and verify recovery. Do not relabel, hide or discard methods to pass
admission. Do not leave a fitting authorized combination unfinished merely because the
category is full.

Update authority is independent of category. Publisher-maintained domain skills remain
publisher-maintained. Business-authored methods retain their declared category and their
existing authorized adoption process. The historical `business` package tier is not an
implicit synonym for every domain method. Actual membership and classifications come
from the release declarations, not an old proposed mapping.

## Authority and execution

Methods operate within the active task's authorization and enforced capabilities. Source
references to global hooks, credentials, publication or standing review gates do not
expand that authority. Follow system and developer instructions and the user's current
direction over conflicting source text. Complete authorized work without a repeated
permission request or a compulsory model consensus. Preserve explicitly requested
interactive workflows and ask for genuinely missing decisions when they are needed.

Tool-capable delegated work uses the existing admission and lease entry with a task,
capsule, workspace, model and scoped ownership. Shared reads are ordinary. Coordinate or
isolate overlapping writes. An admission or integrity rejection stops its dependent
action: correct the defect and rerun the same current check. Do not substitute a raw spawn
route, weaker validator or increased allowance to obtain a pass. Fleet instructions name
the configured route; unrelated methods need not repeat its configuration.

## Sources, verification and recovery

Resolve sibling references from the native skill directory. A missing required tool or
external companion is a concrete limitation; do not restore an old loader or claim an
unperformed operation. Historical references can preserve expertise without becoming
operative instructions. Never move a mixed credential and history container wholesale.

Instruction-only updates need a wording comparison against the user's requirements and
inspection of actual loading. They do not acquire sentence snapshots, phrase tests,
coverage quotas or a new review stage. Executable enforcement changes need evidence at
the affected behavioral boundary: the prohibited effect is blocked and permitted work
succeeds. A script, written rule, valid configuration or source hash alone does not prove
live enforcement. Report only the launch, delivery and recovery paths actually checked.

Use the current versioned authoring, admission, publication and activation mechanisms.
Preserve exact originals and provenance, retain the previous release, and keep uncertain
sources inactive until resolved. Recovery must preserve later conflicting edits. Inspect
status read-only; do not use a mutating restore as a status check. Once the relevant
checks pass, complete the requested delivery rather than adding another review cycle.
